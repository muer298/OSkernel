## 二、选型结论

### 优先原则

- **官方评测接口优先于个人技术偏好**。区域技术方案没有明确标出 ISA、镜像格式和系统调用列表。公开的全国赛资料曾涉及 RISC-V64 + LoongArch64，但不能据此断定这次区域赛要求完全相同。
- 评测通过率是内核赛道的首要功能指标。不要先开发桌面图形界面、网络栈或与测例无关的性能花活。
- 选用团队能审计、能定位问题、能写清楚的技术路线。本示例用 C + 少量 RISC-V 汇编，是为最快验证内核最底层接口；正式工程可基于合法开源的教学内核扩展，前提是遵守赛规的原创贡献与来源说明。
- 用户具备编译器 / SSA/CFG / 二进制语义分析经验，适合负责 trap/syscall ABI、ELF 装载、调试与评测链路，未必要负责设备驱动的全部细节。

### 推荐内核总体结构（目标，不代表已完成）

```
用户测试程序（由官方提供）
          |
    系统调用 ABI
          |
进程/线程、ELF 装载和调度器
     /                  \
内存管理（页框、页表）   VFS / 文件描述符
     \                  /
        Trap/中断与设备层
          |
   RISC-V64 / 其他官方 ISA
```

## 三、模块优先级与验收标准

| 优先级 | 模块 | 最小可测验收 | 常见失败模式 |
|---|---|---|---|
| P0 | 构建与评测适配 | 官方 Docker 内编译、指定产物、至少一次在线有效分数 | 分支、文件名、工具链不符 |
| P0 | 引导、异常和中断 | 启动日志、trap 保存恢复、定时器稳定运行 | CSR 不匹配、栈被破坏 |
| P0 | U-mode 和系统调用 | 运行单个测试 ELF，`write/exit` 可用 | ABI、用户指针检查失败 |
| P0 | 内存 | 页框管理、Sv39、用户/内核隔离、页错误处理 | 映射权限错误、设备树覆盖 |
| P1 | 进程与调度 | `fork/exec/wait/exit` 基础路径；多程序切换 | zombie 泄漏、锁和 TLB 错误 |
| P1 | 文件与 FD | `open/read/write/close/dup/pipe`，按测例增补 | 路径、offset、错误码不一致 |
| P1 | 官方全集回归 | 对所有已公开测例逐条记录 pass/fail | 只挑通过用例、忽略退化 |
| P2 | 性能 | 关键热路径 profile 后针对性优化 | 先优化再补正确性 |
| P2 | 多核/第二 ISA | **只有官方需要或 P0/P1 稳定后**再进入 | 并发 bug、重复移植 |

以上系统调用仅作为类 Unix 内核常见任务的规划示例，是否必须实现以官方测例为准。

## 五、推荐分工（3 人）

| 角色 | 主要任务 | 不可分割的交付 |
|---|---|---|
| A：内核接口/验证 | 启动、trap、syscall/ELF、评测自动化与结果审计 | 官方测试记录、ABI 文档、回归脚本 |
| B：内存/任务 | 页框、页表、进程结构、调度和中断 | 单元测试、隔离/上下文切换测例 |
| C：文件/工程 | VFS、设备、文件描述符、Docker/README/视频 | 文件测试、容器构建、交付材料 |

两人时合并 B/C；一人时先 P0 + 一组最小官方测例，谨慎承诺完整 POSIX 支持。

## 六、正确的迭代闭环

1. 取官方测试清单，建立 `test_id / 目标行为 / 所需 API / 失败签名 / 当前状态` 表。
2. 一次只改动一层内核职责，单元测试、QEMU 冒烟和已通过官方测例全部重跑。
3. 保存 Docker 版本、源代码提交哈希、测试输入、退出码、耗时与串口日志。
4. 将失败分为 `BUILD`、`BOOT`、`TRAP`、`MEMORY`、`SYSCALL`、`FS`、`PERFORMANCE`。
5. 文档同步记录设计取舍，不在最后一周回忆式补写。

## 七、首次一周的具体任务

- 联系比赛平台获取 **区域赛** 2026-10-16 后的评测说明、GitLab 示例项目和可公开测试程序。
- 核对官方是否要求 `make all`、`kernel-rv`/`kernel-la`、`disk.img` 等：这些曾出现在全国赛团队仓库中，**不是当前区域赛 PDF 明示要求**。
- 用本仓库 `make test` 建立算法级单元测试纪律，再用 `make smoke` 做 QEMU 启动验证。
- 第一次向官方平台提交前，必须与平台规定的编译/产物/API 完全对齐。
- 若官方要求两个 ISA，准备 `arch/<ISA>/` 抽象层和双架构构建目标；不要把 RISC-V 专属 CSR/汇编传播到进程与 VFS 模块。

## 八、当前原型的诚信声明

这份 starter 的 `BOOT_OK` **仅表示 UART 和 16 页静态内存池自检通过**；不是操作系统功能测试、不是性能测试、更不是在线有效分数。初版设计和代码由 AI 辅助生成，须由团队逐文件理解、审查与重写/扩展，按官方要求形成实质性学生贡献。
